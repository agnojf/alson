# Closure Report Skill
**AI-generated by:** Alson (A.I Agent)

This skill runs a reusable ACTS workflow for producing a verified Project Closure Report. Read `CONTEXT.md` first, then load only the files required by the selected route.

## Scope

Use this skill for:

- drafting a closure report for a completed project or phase;
- revising a report after a quality finding;
- measuring a current-run report against its acceptance criteria;
- producing the next-action handoff after a passed quality gate;
- showing run status or resuming a blocked or paused run.

Do not use this skill for:

- authorizing project closure or approving the report;
- producing a status report, lessons-learned register, or benefits plan;
- producing a standalone handover document;
- performing a post-implementation review or benefits assessment.

## Core Contract

The pipeline is:

```text
Build -> Measure -> Learn
           ^
           |
      correction to Build
```

Every stage follows:

```text
Declared Inputs -> One Transformation -> Declared Outputs
```

Measure is a hard gate. Learn runs only after Measure records a passed gate for the same run.

## Build

### Inputs

- user-confirmed source paths or pasted project evidence;
- `references/definition.md`;
- `references/closure-report-template.md`;
- an optional Measure audit for a correction cycle;
- an optional user-confirmed prior-run `what-now.md`;
- the current `run-state.md` when resuming.

### Transform

Turn the declared evidence into one factual, concise Project Closure Report. Extract project facts, closure scope and date, results, deliverables, acceptance status, open items, handoff, lessons, administrative closure, approval status, and repository evidence. Do not invent facts. Mark unresolved facts and approval gaps clearly.

Ask one focused question at a time only when a missing fact or decision is required. If a draft can proceed with a documented gap, preserve the gap for Measure rather than guessing.

### Outputs

Write only:

- `{{RUN_PATH}}/stages/01-build/closure-report.md`;
- `{{RUN_PATH}}/stages/01-build/build-handoff.md`;
- `{{RUN_PATH}}/run-manifest.md`;
- `{{RUN_PATH}}/run-state.md`.

The report leads with the closure result and includes the configured sections. The handoff lists exact current-run paths and items for Measure to verify.

### Verify

- source evidence is reflected accurately;
- all report sections are present or the gap is explicit;
- approval names are not presented as approval evidence;
- the report and handoff belong to the current run;
- a correction finding is resolved or remains traceable;
- no legacy output is used as current evidence.

If verification fails and cannot be corrected with available information, write `Blocked` state and stop.

## Measure

### Inputs

- `{{RUN_PATH}}/stages/01-build/build-handoff.md`;
- every artifact listed in the current Build handoff;
- `references/acceptance-criteria.md`;
- `references/quality-rubric.md`;
- `references/quality-policy.md`;
- `references/run-state-template.md`;
- the current `{{RUN_PATH}}/run-state.md`.

### Transform

Check every applicable acceptance criterion as `Pass`, `Partial`, `Fail`, or `Not Applicable` with evidence. Score every rubric dimension using the configured scale. Calculate the quality percentage without rounding up. Apply the 95% threshold and determine the gate state.

The gate passes only when the score is at least 95%, every applicable criterion passes, every `Not Applicable` result has a reason, and no blocker remains.

When the gate fails, record each finding with evidence, severity, correction, responsible stage, and remeasure condition. Correctable report findings route to Build. Return to Measure after correction. Do not run Learn on a failed or blocked gate.

When required evidence, access, authority, or human judgment is missing, record `Blocked`, one focused request, the last completed stage, and the resume stage before stopping.

### Outputs

Write only:

- `{{RUN_PATH}}/stages/02-measure/audit-findings.md`;
- `{{RUN_PATH}}/run-state.md`.

The audit includes the attempt number, threshold, formula, score, gate result, criterion evidence, rubric scores, corrections, blockers, and next route.

## Learn

### Inputs

- a current-run Measure audit with `Quality gate: Passed`;
- `{{RUN_PATH}}/stages/01-build/closure-report.md`;
- `{{RUN_PATH}}/stages/01-build/build-handoff.md`;
- `references/what-now-template.md`;
- `references/quality-policy.md`;
- `references/run-state-template.md`;
- the current `{{RUN_PATH}}/run-state.md`.

### Transform

Assess the achieved outcome and select the smallest evidence-based next move. Separate agent actions from human decisions. Rank actions by dependency, impact, and urgency. Write one clear recommendation and the first executable action.

If the user asks to choose among actions, present the ranked actions and pause for that decision. Do not treat silence as acceptance or rejection.

### Outputs

Write only:

- `{{RUN_PATH}}/stages/03-learn/what-now.md`;
- `{{RUN_PATH}}/run-state.md`.

Mark the run `Complete` only after `what-now.md` is verified. A missing decision-maker response after a passed quality gate is `Governance pending`, not a quality failure.
