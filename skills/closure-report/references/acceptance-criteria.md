# Acceptance Criteria -- Project Closure Report

A closure report passes when every criterion below is met.

| # | Criterion | Pass Condition |
|---|-----------|---|
| 1 | Project identity stated | Project name, scope of closure, and closure date are documented |
| 2 | Closure reason documented | The report states why the project or phase is being closed |
| 3 | Final deliverables recorded | Final deliverables are listed with acceptance status and who accepted them |
| 4 | Delivery performance summarized | Final scope, schedule, cost, and quality status is summarized with planned vs actual |
| 5 | Outstanding items tracked | All outstanding items have owners and target actions. If none, state that explicitly |
| 6 | Handover status documented | Transition or handover status is documented |
| 7 | Lessons learned captured | Key lessons are captured and actionable |
| 8 | Administrative closure documented | Financial, contractual, and repository closure status is documented |
| 9 | Approvals included | Required approval roles are listed with name, signature, and date fields |
| 10 | Repository location recorded | The report states where it is stored in the project repository |
| 11 | Concise writing | No filler paragraphs, repetition, or unnecessary sections. Document leads with the answer |
| 12 | Source notation present | Every factual claim is marked stated, inferred, or unknown |
