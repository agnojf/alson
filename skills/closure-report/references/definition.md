# Project Closure Report -- Definition

A **closure report** is a formal document created at the end of a project or phase to confirm work is complete, summarize results, document outstanding items and handoff, and capture key lessons for future use.

It typically explains:

- what the project set out to achieve,
- what was delivered and with what acceptance status,
- how the project performed against scope, schedule, cost, and quality,
- any remaining handoff or follow-up items with owners and target actions,
- lessons learned during execution,
- administrative and contractual closure status,
- approvals or signatures confirming formal closure.

It serves two main purposes: it gives stakeholders a clear record that the project is closed, and it preserves knowledge for future projects. It is stored in the agreed project repository as part of the official project record.

## Delivery Framing

Frame the report around these themes:

- **Closure summary** -- what was closed, why, and when
- **Delivery performance** -- how actual results compare to planned scope, schedule, cost, and quality
- **Accepted deliverables** -- what was delivered and formally accepted
- **Open items** -- what remains and who owns each item
- **Lessons learned** -- what to start, keep, or stop doing
- **Administrative closure** -- contracts, finances, repository
- **Approvals** -- who signed off and when
