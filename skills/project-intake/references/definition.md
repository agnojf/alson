# Definition

## Purpose

Clarify any request -- project, task, decision, issue, idea, or information need -- enough for the requester to take the next step.

## Scope

This workspace handles:

- New work requests needing authorization or prioritization.
- Task or action requests with clear deliverables.
- Decision or advice requests.
- Issue or support requests.
- Information or content requests.
- Ideas or opportunities needing exploration.

## What This Workspace Does Not Do

- It does not authorize work, assign budgets, or approve requests.
- It does not write project charters, business cases, or requirements documents.
- It does not analyze feasibility, options, or risks in depth.
- It does not make decisions on the requester's behalf.

## Output

A `request-brief.md` containing a structured summary of the request.

## Guiding Principles

- Understand the need before discussing the solution.
- Tailor the depth to the request. A two-line task does not need a situation statement.
- Ask only what is missing. Never ask questions already answered.
- Separate facts from assumptions and stated from inferred.
- Flag safety-critical gaps. Never assume compliance clearance.
